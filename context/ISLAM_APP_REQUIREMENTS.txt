FORMAI - ISLAM (iOS APP) REQUIREMENTS AND SYSTEM DESIGN
Owner: Islam. Read 00_INTEGRATION_CONTRACTS.txt first.

Your job: a Swift app that opens the camera, runs MediaPipe pose, counts reps with simple rules, runs Syed's Core ML model on each rep, and speaks the feedback. You build everything except the model weights and the training data.


1. WHAT YOU DELIVER

A working iOS app with this loop, for squat and curl:
  camera -> MediaPipe pose (33 landmarks) -> rep counter (rule-based) -> on rep complete: preprocess -> Core ML model -> spoken cue


2. CRITICAL: BUILD AGAINST SYED'S DUMMY MODEL FROM DAY 0

Syed gives you a DUMMY .mlpackage with correct input/output shapes on day one. Wire your entire inference path against it immediately. When the real model lands it is a file swap, nothing else changes. Do not wait for training to finish.


3. STACK

  Language     : Swift, SwiftUI
  Camera       : AVFoundation (AVCaptureSession, video frames)
  Pose         : MediaPipeTasksVision (CocoaPod), Pose Landmarker, LIVE_STREAM mode
  Inference    : Core ML (the .mlpackage from Syed, compiled into the app)
  Voice        : AVSpeechSynthesizer (on-device text to speech)

On voice: use AVSpeechSynthesizer for the hackathon. It is on-device, zero-latency, needs no network or API keys, and cannot fail mid-demo. Vapi (which the team used in Rehabify) is a later upgrade for conversational coaching; do not put a network dependency on the critical demo path now.

Pose detector note (do not deviate): MediaPipeTasksVision, NOT Apple Vision. Syed's model is trained on MediaPipe's 33 landmarks. Apple Vision uses a different landmark set and would silently break the model. Same detector both sides is the whole reason this integrates. You and Mahmoud both use MediaPipe Pose Landmarker.


4. PODFILE / SETUP

  pod 'MediaPipeTasksVision'

Bundle pose_landmarker_full.task into the app (same task file family Mahmoud used offline). Add the two .mlpackage files from Syed to the Xcode target; Xcode compiles them to .mlmodelc automatically and generates a Swift class per model.

Permissions: NSCameraUsageDescription in Info.plist.


5. THE LOOP IN DETAIL

  a) AVCaptureSession streams frames.
  b) Each frame -> MediaPipeTasksVision PoseLandmarker (LIVE_STREAM) -> 33 landmarks, each (x, y, z, visibility), x/y normalized to [0,1]. This matches Mahmoud's offline schema exactly (contracts section 3).
  c) Rep counter (contracts section 8), rule-based:
       Squat: compute left_knee_angle = angle(hip23, knee25, ankle27).
         DOWN when < 100 deg, UP when > 160 deg. Count rep on DOWN->UP.
       Curl: compute right_elbow_angle = angle(shoulder12, elbow14, wrist16).
         FLEXED when < 60 deg, EXTENDED when > 150 deg. Count rep on FLEXED->EXTENDED.
       Buffer the landmark frames spanning the current rep.
  d) On rep complete: take the buffered frames, run the SAME preprocessing Syed defined (contracts section 7) -> [32, F] -> shape to MLMultiArray (1, 32, F) named keypoint_window.
  e) Run the matching Core ML model -> form_logits (1, NUM_CLASSES). Apply softmax, take argmax, map index to label via model_card.class_labels.
  f) Map label to a short spoken cue and speak it with AVSpeechSynthesizer. Examples:
       squat: good -> "Nice depth", knee_valgus -> "Push your knees out",
              insufficient_depth -> "Go lower", back_rounding -> "Chest up, flat back"
       curl:  good -> "Clean rep", swing -> "Stop swinging, control it",
              partial_rom -> "Full range, all the way up", elbow_flare -> "Tuck your elbow in"
  g) Update the rep counter and a live form score on screen.


6. PREPROCESSING PORT (your only tricky task)

You must reimplement Syed's preprocess_rep in Swift, matching contracts section 7 step for step: hip-center origin, torso-length scale, the exact ordered feature list (feature_order in model_card.json), angles divided by 180, then linear-interpolate the rep's frames to exactly 32.

Validation gate: Syed gives you a golden .npy (three preprocessed reps with known input landmarks and known output [32,F]). Feed the same input landmarks through your Swift code and confirm you reproduce the output within 1e-3. If the golden test passes, the model will behave on-device exactly as in Syed's testing. If it fails, the model is being fed numbers it never saw and predictions are garbage. Do this test before trusting any model output.

Left-arm curl: if the user selects left arm, mirror horizontally (negate normalized x for all landmarks) so a left-arm rep looks like a right-arm rep to the model. One model, both arms. Detail in contracts section 7.


7. FALLBACK (keep the demo bulletproof)

Your rep counter already computes the key joint angles. If the ML model is weak on demo day (limited training data is the main risk), you can drive cues directly from thresholds on those angles, exactly like Rehabify did:
  squat: knee_angle minimum per rep < target depth -> "Go lower"; knee_x inside ankle_x -> "Knees out".
  curl:  elbow_angle range too small -> "Full range"; shoulder y moving a lot -> "Stop swinging".
Build the threshold path as a toggle. Default to the model; flip to rules if needed. Either way the demo shows live form correction.


8. UX FOR THE DEMO (judging weights presentation 20 percent)

  - A framing guide overlay so the user stands where Mahmoud's training videos were shot (contracts section 4). Same view = model in-distribution.
  - Live skeleton overlay (draw the 33 landmarks). It looks impressive and proves the CV is real.
  - Big rep counter, a form score, and the last spoken cue as text.
  - Exercise picker: Squat or Curl (and arm select for curl).
Keep it to these screens. Narrow scope, polished, is what wins.


9. HOW YOUR INPUTS CONNECT

  From Syed: two .mlpackage files (input keypoint_window (1,32,F), output form_logits), two model_card.json files (feature_order, class_labels), and a golden .npy. That is your whole interface to the model.
  From Mahmoud: nothing direct. You rely on the shared fact that you both run MediaPipe Pose Landmarker, so live landmarks match training landmarks. Confirm with him you pinned MediaPipeTasksVision.


10. ACCEPTANCE CHECK (you are done when)

  - app shows live camera + skeleton overlay + rep count for both exercises.
  - Swift preprocessing reproduces Syed's golden .npy within 1e-3.
  - the real .mlpackage loads and produces a label per rep; cues are spoken via AVSpeechSynthesizer.
  - left-arm curl mirrors correctly.
  - rule-based fallback toggle works without the model.
